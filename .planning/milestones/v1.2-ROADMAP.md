### Phase 19.2.1: Different Players Showing Same Stats (INSERTED)

**Goal**: Fix bug where different players in the same position show identical predicted stats instead of player-specific predictions
**Depends on**: Phase 19.2
**Plans**: 2/2 complete

Plans:
- [x] 19.2.1-01: Diagnose window parameter mismatch in player feature computation — completed 2026-01-20
- [x] 19.2.1-02: Fix window parameter (3→5) in roster.py and verify player-specific predictions — completed 2026-01-20

**Outcome**: Fixed window parameter mismatch causing identical predictions. Root cause: Models trained with window=5 (Phase 19.1-02) but API computed window=3 features. Feature keys (roll3 vs roll5) didn't match, so dict.update() merged player features with position defaults without overwriting. Result: All players received identical position-typical predictions. Fix: Updated _compute_rolling_stats_for_player and _compute_volatility_for_player to window=5. Different players now produce different predictions based on individual performance history.

### Phase 21: Position-Specific Tuning

**Goal**: Retrain all ML models with Phase 20 expanded feature set (40 features) - position-by-position analysis and comparison
**Depends on**: Phase 20
**Plans**: 4/4 complete

Plans:
- [x] 21-01: QB models with 40-feature set — completed 2026-01-22
- [x] 21-02: RB models with 40-feature set — completed 2026-01-22
- [x] 21-03: WR/TE models with 40-feature set — completed 2026-01-22
- [x] 21-04: K/DEF models with 40-feature set — completed 2026-01-22

**Outcome**: All 32 models retrained with 40-feature set (weather, injury, Vegas additions). Cross-position comparison reveals predictability hierarchy:

**Position Rankings (Average R²):**
- K (Kicker): ~0.47 — Highest predictability
- TE (Tight End): 0.367
- RB (Running Back): 0.362
- QB (Quarterback): 0.355
- DEF (Defense): ~0.30
- WR (Wide Receiver): 0.274 — Lowest predictability

**Key Insights:**
- K models surprisingly outperform all skill positions due to weather features directly affecting kicking (wind, cold, precipitation)
- TE more predictable than WR: usage consistency vs coverage variance/game script volatility
- Volume metrics (receptions, carries, fg_att) consistently outperform production metrics (yards, TDs) across all positions
- Weather feature asymmetry: High value for K, moderate for QB/RB (shifts pass-run balance), low for DEF (affects both sides equally)
- DEF inherently unpredictable: opponent-dependent, high-variance defensive stats (sacks, turnovers)

Models archived to models_archive/phase20_pre_tuning/ before retraining for rollback capability.

## Milestone Summary

**Decimal Phases:**
- Phase 19.1: Re-evaluate Recent Performance Metrics (inserted after Phase 19 for data quality improvements)
- Phase 19.2: Improve Model Confidence & Accuracy (inserted after Phase 19.1 for metric fixes)
- Phase 19.2.1: Different Players Showing Same Stats (inserted after Phase 19.2 for critical bug fix)
- Phase 21.1: Revamp Prediction Visualizations (inserted after Phase 21 for transparency features)

**Key Decisions:**

**Performance & Architecture:**
- Decision: Do NOT adopt ensemble models (Rationale: Single models win 20/21 stats; 0.890 correlation too high for ensemble benefit; simpler architecture preferred)
- Decision: Keep LightGBM as production default (Rationale: 7x faster than XGBoost, wins 81% of benchmarks)
- Decision: Virtualize player dropdown with react-window (Rationale: 6KB bundle, renders only visible items, solves lag)

**Data Quality & Features:**
- Decision: 5-game rolling window with shift(1) (Rationale: Prevents data leakage, captures recent trends better than 3-game)
- Decision: 2022-2025 training data (4 years) (Rationale: Excludes COVID-era noise, maximizes recency for 2026 predictions)
- Decision: 40-feature set with weather/injury/Vegas (Rationale: Weather asymmetrically valuable for K; Vegas lines predict game script)
- Decision: Always add Vegas features when API unavailable (Rationale: Neutral values (spread=0.0, total=45.0) maintain schema consistency, prevent "missing column" errors)

**Model Quality & Metrics:**
- Decision: R²-based accuracy (100*R²) (Rationale: Scale-independent, correlates with model quality; fixes "49% accuracy for R² 0.545" problem)
- Decision: Confidence tiers based on R² only (Rationale: High >0.5, Medium 0.3-0.5, Low <0.3; simpler than dual-metric system)
- Decision: Fixed window=5 parameter mismatch (Rationale: Models trained with roll5 features, API computed roll3; key mismatch caused identical predictions)

**Validation & Transparency:**
- Decision: Holdout validation over walk-forward (Rationale: Train once (30-60min) vs retrain 18 times (12-24hrs); ~20x speedup with equivalent validity)
- Decision: 10 Optuna trials for validation models (Rationale: Quick validation, still achieves R² 0.585 average)
- Decision: Separate models_holdout directory (Rationale: Prevents overwriting production models, enables side-by-side comparison)

**UI/UX:**
- Decision: Synchronized Recharts with syncId (Rationale: Hover on one chart shows tooltips across all stats for same week)
- Decision: Use headshotUrl from Convex (Rationale: Eliminates flickering from redundant ESPN URL fetching; ESPN as fallback)
- Decision: 45-48vw drawer width (Rationale: Balance between chart visibility and screen real estate)

**Issues Resolved:**

- Fixed player selection lag (virtualization)
- Fixed scale-dependent accuracy formula (R²-based)
- Fixed identical player predictions (window parameter mismatch)
- Fixed headshot flickering (use Convex headshotUrl)
- Fixed data leakage in rolling features (shift(1))
- Evaluated ensemble models (rejected based on benchmarks)

**Technical Insights:**

- K (kicker) models most predictable position (~0.47 R²) due to weather feature asymmetry
- TE more predictable than WR (0.367 vs 0.274) - usage consistency vs coverage variance
- Volume metrics consistently outperform production metrics across all positions
- Holdout validation R² 0.585 average (train 2022-2024, test 2025)
- 34,699 predictions validated across 662 players
