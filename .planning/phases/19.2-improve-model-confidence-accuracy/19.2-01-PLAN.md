<task type="auto">
  <name>Task 2: Evaluate alternative accuracy metrics</name>
  <files>.planning/phases/19.2-improve-model-confidence-accuracy/ACCURACY_AUDIT.md</files>
  <action>
    Add "Alternative Metrics" section to ACCURACY_AUDIT.md evaluating 3 options:

    **Option 1: R²-based accuracy**
    - Formula: accuracy_pct = max(0, 100 * R²)
    - Pros: Standard ML metric, directly measures variance explained, always 0-100%
    - Cons: Can be negative for very bad models (clamp to 0), less intuitive for non-ML users
    - Example: R² 0.545 → 55% accuracy (matches performance)

    **Option 2: MAPE (Mean Absolute Percentage Error) inverted**
    - Formula: accuracy_pct = max(0, 100 * (1 - MAPE/100))
    - Pros: Percentage-based like current formula, handles different scales naturally
    - Cons: Undefined for actuals=0, can explode for small values (fumbles issue persists)
    - Example: MAPE 30% → 70% accuracy

    **Option 3: Skill Score (variance-normalized)**
    - Formula: skill_score = 1 - (MAE / std(actuals)), accuracy_pct = max(0, 100 * skill_score)
    - Pros: Accounts for stat variance, better for high-variance stats (TDs), 0-100% scale
    - Cons: More complex calculation, less standard than R²
    - Example: MAE 17.69, std 36.96 → skill 0.521 → 52% accuracy

    **Recommendation:**
    - Primary: Use R²-based accuracy (Option 1) - standard ML metric, aligns with model performance
    - Secondary: Keep skill score as "consistency" metric for stats with high variance
    - Update confidence tiers to use R² thresholds: High (R² > 0.5), Medium (R² 0.3-0.5), Low (R² < 0.3)
  </action>
