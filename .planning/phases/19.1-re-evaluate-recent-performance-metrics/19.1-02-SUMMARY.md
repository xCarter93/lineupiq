**Key Discovery:**
The existing code did NOT use shift(1) for data leakage prevention in rolling stats, despite being mentioned in STATE.md decision 13-02. This was a critical bug - rolling features were including the current game's value that we're trying to predict. This has now been fixed.

**With shift(1):**
- Week 1: null (no prior games)
- Week 2: avg of week 1 only
- Week 3: avg of weeks 1-2 only

This ensures we only use information available before the game being predicted.

## Technical Notes

### Data Leakage Fix
The addition of shift(1) is a significant improvement. Without it, when predicting week 3's stats:
- **Before (incorrect)**: Rolling avg = mean(week1, week2, week3) - includes the game we're predicting!
- **After (correct)**: Rolling avg = mean(week1, week2) - only uses prior games

This ensures model training and inference use only information that would have been available before the game.

### Training Window Rationale
Using 2022-2025 (4 years) instead of 2020-2025 (6 years):
- Avoids COVID-era noise from 2020-2021 seasons
- Maximizes recency for 2026 predictions
- Includes most recent 2025 season data
- Balances data volume with pattern relevance

### Rolling Window Expansion Rationale
Expanding from 3 to 5 games:
- Better captures trends for volatile stats (TDs, turnovers)
- Example: Jalen Hurts threw 1-3 TDs over last 5 games, old 3-game window missed this pattern
- Still recent enough to weight current form
- Provides more data points for early-season predictions
