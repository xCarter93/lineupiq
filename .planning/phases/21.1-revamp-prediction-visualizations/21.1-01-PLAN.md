  <action>
Create holdout.py module with functions for holdout validation:

1. `train_holdout_models(train_seasons: list[int], positions: list[str], n_trials: int = 30, output_dir: str = "models_holdout")`:
   - Train all 32 models using data from specified training seasons only
   - Use train_all.py patterns (Optuna, LightGBM defaults, configurable trials)
   - Save models to specified output directory (default: models_holdout/)
   - Return dict of model paths by position/target
   - Example: train_holdout_models([2022, 2023, 2024], ["QB", "RB", ...])

2. `predict_season(season: int, model_dir: str, positions: list[str], weeks: list[int] | None = None)`:
   - Load player data for all weeks of specified season from nflreadpy
   - Compute features for all active players across all weeks
   - Run predictions using models from model_dir
   - Return DataFrame with columns: [player_id, player_name, position, season, week, target, predicted_value, actual_value]
   - If weeks specified, only predict those weeks; otherwise predict all available weeks

Design principles:
- Reuse existing training infrastructure from train_all.py
- Models never see holdout season data during training (prevents data leakage)
- Predict entire season in one pass (much faster than per-week retraining)
- Save models separately to avoid overwriting production models
- Validate that holdout season is not in training seasons (raise error if overlap)

Create CLI script for running 2025 holdout validation:

```python
"""
Generate 2025 season predictions using holdout validation.

Trains models on 2022-2024 data only, then predicts entire 2025 season.
This proves model quality on completely unseen data.

Usage:
  # Full validation (all weeks, 30 trials, ~45-60 min)
  uv run python scripts/validate_2025_holdout.py

  # Quick mode (10 trials, ~20-25 min)
  uv run python scripts/validate_2025_holdout.py --quick

  # Specific positions or weeks
  uv run python scripts/validate_2025_holdout.py --positions QB RB --weeks 1 2 3 4

  # Use existing models (skip training)
  uv run python scripts/validate_2025_holdout.py --use-existing models_holdout/
"""

Features:
- Parse CLI args with argparse (--positions, --weeks, --quick, --output, --trials, --use-existing)
- Default: train on [2022, 2023, 2024], predict all 2025 weeks, all positions, 30 trials
- --quick flag: 10 trials (faster training)
- --use-existing: skip training, use pre-trained models from specified directory
- Call train_holdout_models() from holdout.py (unless --use-existing)
- Call predict_season() to predict 2025
- Output predictions to JSON file: validation_2025_predictions.json
- JSON structure: array of {player_id, player_name, position, week, target, predicted_value, actual_value}
- Progress logging: "Training models on 2022-2024...", "Predicting 2025 season...", "Computing metrics..."
- Summary stats: total predictions, MAE by position, R² by position, accuracy % by position

Error handling:
- Check if 2025 data available (graceful error if season incomplete)
- Validate no overlap between train and test seasons
- Handle missing player data gracefully (log warning, continue)
