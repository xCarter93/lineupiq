## Decisions Made

**1. Three compound indexes for different query patterns**
- by_player_week: Get all predictions for a player across weeks (player detail view)
- by_position_week: Get all players in a position for a week (position aggregate metrics)
- by_season_week: Get all predictions for a week (season-wide analysis)
- Rationale: Supports three distinct frontend access patterns efficiently

**2. Batch size 100 for Convex upload**
- Convex has transaction limits; 100 is safe batch size
- Balances API throughput with memory constraints
- Pattern consistent with other bulk upload scripts (playerHistory.ts uses 100)

**3. Transform field names in upload script**
- JSON uses snake_case (player_id, predicted_value)
- Convex expects camelCase (playerId, predictedValue)
- Transformation happens in upload script via transform_prediction() helper
- Keeps Convex schema clean and TypeScript-friendly

**4. Compute error fields during upsert**
- error = predictedValue - actualValue
- absoluteError = Math.abs(error)
- Computed in mutation handler, not stored in source JSON
- Reduces storage duplication and ensures consistency
