<task type="checkpoint:human-verify" gate="blocking">
  <what-built>
Complete Phase 17 implementation:
1. Dashboard grid layout replacing vertical stack
2. SHAP-based explainability panel with feature contribution bars
3. Natural language prediction summaries
4. Player headshot avatars throughout the app
5. Expandable detail view (top 3-5 factors → full breakdown)
  </what-built>
  <how-to-verify>
**Setup:**
1. Start backend: `cd packages/backend && uv run uvicorn lineupiq.api.main:app --reload`
2. Start frontend: `cd packages/frontend && pnpm dev`
3. Ensure roster is synced (Admin page → "Sync 2025 Roster" if needed)

**Test the dashboard grid layout:**
1. Visit http://localhost:3000/matchup
2. Select a player (e.g., Patrick Mahomes)
3. Select opponent team and submit prediction
4. **Desktop (>1024px):** Verify 3-column layout:
   - Left: Fantasy points card with player avatar
   - Middle: Stat projections and player history
   - Right: Explainability panel
5. **Tablet (768-1024px):** Verify 2-column or adjusted layout
6. **Mobile (<768px):** Verify all content stacks vertically

**Test the explainability panel:**
1. After prediction loads, verify "Why this projection?" panel appears
2. Check natural language summary is coherent (e.g., "Projected 298 passing yards — boosted by...")
3. Verify top 3-5 feature bars are shown with:
   - Human-readable names (not raw feature names)
   - Green bars for positive contributions
   - Red bars for negative contributions
4. Click "Show all factors" — verify remaining features appear
5. Verify bars are sorted by impact (biggest first)

**Test player headshots:**
1. In player dropdown, verify small avatars appear next to player names
2. In fantasy points card, verify player avatar appears
3. If a player has no headshot, verify initials fallback works

**Decision support check (the essential goal):**
- Can you quickly understand WHY the model made this prediction?
- Does the explanation help you decide whether to trust the projection?
- Is it clear which factors are helping vs. hurting the projection?
  </how-to-verify>
  <resume-signal>
Type "approved" if all checks pass.
If issues found, describe what needs fixing (e.g., "bars not colored correctly", "mobile layout broken", "summary text unclear").
  </resume-signal>
