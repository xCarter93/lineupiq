## Bug Fix Summary

**The Problem:**
After Phase 19.1-02 expanded the rolling window from 3 to 5 games, all models were retrained with roll5 features. However, the API prediction endpoint was NOT updated to match. This caused a feature key mismatch:
- Models expected: `passing_yards_roll5`, `rushing_yards_roll5`, etc.
- API computed: `passing_yards_roll3`, `rushing_yards_roll3`, etc.

When the API merged player-specific features with position defaults using dict.update(), the roll3 keys didn't overwrite the roll5 defaults. Result: all players received identical position-typical defaults → identical predictions.

**The Fix:**
Changed default window parameter from 3 to 5 in two helper functions:
- `_compute_rolling_stats_for_player(history_df, window=5)`
- `_compute_volatility_for_player(history_df, window=5)`

This simple 2-line change ensures the API computes roll5 features that match model expectations.

**The Impact:**
- Different players now get different predictions based on their actual performance
- Rolling stats properly reflect player-specific recent trends (5-game window)
- Feature keys (roll5) align with model training
- Player-specific features now overwrite position defaults correctly

## Technical Notes

**Key Learning:**
Python's dict.update() method only overwrites keys with matching names. When feature keys don't match (roll3 vs roll5), the original values (defaults) remain unchanged. This is a subtle but critical detail in feature merging logic.

**Blast Radius:**
This bug affected ALL predictions for ALL positions since Phase 19.1-02 (when rolling window was changed to 5). Every player prediction between then and now used position defaults instead of player-specific stats. The fix restores player-specific predictions across the board.

**Prevention:**
When changing feature computation parameters (like window size), ensure ALL parts of the pipeline are updated:
1. Feature engineering (pipeline.py) ✅ Updated in Phase 19.1-02
2. Model training ✅ Updated in Phase 19.1-02
3. API prediction endpoint ❌ Missed in Phase 19.1-02 → Fixed in Phase 19.2.1-02
