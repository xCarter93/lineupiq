# Phase 19.2.1: Different Players Showing Same Stats - Context

**Gathered:** 2026-01-20
**Status:** Ready for research

<vision>
## How This Should Work

This is a surgical bug fix with a clear diagnostic-first approach. The vision is to systematically audit the feature pipeline - rolling stats, player history, aggregation logic - to understand exactly where player identity is being lost or pooled incorrectly.

Once we understand the root cause through systematic investigation, the fix should be obvious and minimal. This isn't about rebuilding the feature pipeline; it's about finding the specific place where player-specific data stops flowing through and fixing just that.

The outcome is simple: when you predict stats for QB1 vs QB2, they should get different predictions based on their individual performance histories, not identical position-level predictions.

</vision>

<essential>
## What Must Be Nailed

- **Root cause understanding** - Know exactly why different players produce identical predictions before changing any code
- **Verified fix** - The bug is fixed AND we can demonstrate that different players (e.g., QB1 vs QB2) produce different predictions based on their individual histories
- **Both are equally critical** - Understanding and fixing go hand-in-hand; can't have one without the other

</essential>

<specifics>
## Specific Ideas

**Investigation approach:**
- Audit the feature pipeline systematically (rolling stats, player history, aggregation logic)
- Follow the evidence rather than assumptions - no specific suspicions about where the bug is
- Focus on WHERE player identity gets lost: is it during rolling window computation, feature aggregation, or model input preparation?

**Fix approach:**
- Surgical, minimal code changes once root cause is identified
- The fix should be obvious once we understand the problem

</specifics>

<notes>
## Additional Context

**Context from roadmap:**
The bug manifests as identical predictions for different players in the same position. Roadmap suggests three possible causes:
1. Features computed at position-level instead of player-level
2. Player IDs not being properly used in feature computation
3. Rolling stats aggregation incorrectly pooling across players

**Priority:** Evidence-driven investigation. Let the systematic audit reveal where the problem actually is, rather than starting with assumptions.

</notes>
