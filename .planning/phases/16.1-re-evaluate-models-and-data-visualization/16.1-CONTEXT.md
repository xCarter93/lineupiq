# Phase 16.1: Re-evaluate Models and Data Visualization - Context

**Gathered:** 2026-01-19
**Status:** Ready for planning

<vision>
## How This Should Work

Predictions should be **player-specific**, not position-generic. When I select different QBs - like Jalen Hurts (elite starter with full season of data), Drake Maye (rookie with limited data), and Jarrett Stidham (backup who hasn't played) - I should see **dramatically different** projected fantasy scores.

Right now, all three QBs show **exactly identical** scores, which is clearly wrong. The model has rolling stats, historical performance data, and player-specific features - these should produce meaningfully different predictions for players with different track records.

The visualization (fantasy points trend chart) also isn't working - the axes render but no data points or line appears.

</vision>

<essential>
## What Must Be Nailed

- **Fix the prediction bug first** - Player-specific data must flow through to the model and produce individualized predictions. This is the priority.
- **Identical scores = identical inputs** - The bug is likely in the data flow (API, feature computation, or player lookup), not the model itself.
- **Chart can wait** - Visualization is secondary until predictions actually work correctly.

</essential>

<specifics>
## Specific Ideas

- User tested via the matchup UI after syncing the 2025 roster from the Admin page
- Tested: Drake Maye, Jarrett Stidham, Jalen Hurts - all returned **exactly** the same projected score (not just similar - identical)
- This points to a bug where player-specific features (rolling stats, historical data) aren't being used
- Chart issue: X and Y axes appear but no data points/lines render

</specifics>

<notes>
## Additional Context

The user isn't focused on whether the model is "good enough" - they understand predictions have inherent uncertainty. The issue is that predictions should at minimum **differentiate** between players with vastly different profiles.

A backup QB with 0 games this season getting the same projection as a top-5 QB with a full season of games is a data flow bug, not a model accuracy problem.

</notes>
