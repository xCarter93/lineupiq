# Plan 16.1-01: Fix Player-Specific Predictions

## Problem Statement

All QBs (Drake Maye, Jarrett Stidham, Jalen Hurts) return **exactly identical** projected fantasy scores. This is a data flow bug, not a model accuracy issue.

**Root Cause:** In `packages/frontend/app/matchup/page.tsx:65`, the `createDefaultFeatures()` function creates **hardcoded position-typical values** instead of fetching the actual player's historical rolling stats:

```typescript
// BUG: Every QB gets these exact same hardcoded values
const features = createDefaultFeatures(matchup.position, matchup.isHome);
// Returns: { passing_yards_roll3: 250, passing_tds_roll3: 1.8, ... }
```

The backend has the infrastructure to compute player-specific features (`build_features()` in `features/pipeline.py`) but there's no API endpoint to fetch them for a specific player.

## Solution Overview

1. **Backend**: Create new API endpoint `/api/player/{player_id}/features` that computes and returns player-specific feature values (rolling stats, volatility, team strength)
2. **Frontend**: Update matchup page to fetch player-specific features before making predictions
3. **Fallback**: Keep `createDefaultFeatures()` as fallback for players with no historical data (rookies, backups)

const handleSubmit = async (matchup: MatchupData) => {
  setIsLoading(true);

  try {
    // NEW: Fetch player-specific features
    const playerFeatures = await fetchPlayerFeatures(
      matchup.playerId,
      matchup.opponentTeam
    );

    // Merge with matchup context (isHome, etc.)
    const features: PredictionFeatures = {
      ...playerFeatures.features,
      is_home: matchup.isHome,
      // ... other context fields
    };

    // If insufficient data, fall back to position defaults
    if (!playerFeatures.has_sufficient_data) {
      const defaults = createDefaultFeatures(matchup.position, matchup.isHome);
      features = { ...defaults, ...playerFeatures.features };

1. **Performance**: Computing features on-demand may be slow. Mitigate with caching or pre-computation.
2. **Missing data**: Players with <3 games need graceful fallback. Handle with `has_sufficient_data` flag.
3. **API errors**: Network issues when fetching features. Keep `createDefaultFeatures()` as fallback.
