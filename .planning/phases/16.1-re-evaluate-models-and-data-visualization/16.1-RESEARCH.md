<research_summary>
## Summary

Researched two interconnected domains: (1) ML model evaluation best practices for sports predictions, and (2) data visualization patterns for communicating model accuracy and predictions to end users.

Key findings:
1. **Model calibration matters more than raw accuracy** for decision-making applications like fantasy football
2. **TD prediction is inherently hard** due to high-variance game-script dependency - current 19-66% accuracy is within expected range
3. **Visualization should build trust** through prediction intervals, calibration curves, and trend analysis
4. **Recharts can display confidence bounds** using ComposedChart with stacked Areas, but requires careful data transformation

**Primary recommendation:** Focus on visualizing existing prediction intervals and model confidence rather than trying to improve TD model accuracy (which has diminishing returns). Add calibration visualization and residual analysis to help users understand when to trust predictions.
</research_summary>

### Pattern 1: Calibration-First Evaluation

**What:** Evaluate models by calibration (are 80% confidence predictions right 80% of the time?) rather than raw accuracy.

**Why it matters:** Research shows calibration-based model selection leads to +34.69% ROI vs -35.17% for accuracy-based selection in sports betting contexts.

**Implementation for LineupIQ:**
```python
# Backend: Generate calibration data
from sklearn.calibration import calibration_curve

def generate_calibration_data(y_true, y_pred_proba, n_bins=10):
    """Compute calibration curve for model confidence."""
    prob_true, prob_pred = calibration_curve(y_true, y_pred_proba, n_bins=n_bins)
    return {
        "bins": prob_pred.tolist(),
        "actual": prob_true.tolist(),
        "perfect": prob_pred.tolist(),  # Reference line
    }
```

**Frontend visualization:** Line chart showing predicted vs actual coverage.

### Pattern 2: Confidence Interval Visualization

**What:** Show prediction bounds (upper/lower) alongside point predictions.

### Pattern 3: Position-Specific Accuracy Display

**What:** Show users which predictions are more trustworthy by position/stat type.

**Based on current data:**
```typescript
const ACCURACY_TIERS = {
  high: { threshold: 75, color: "green", label: "High confidence" },
  medium: { threshold: 50, color: "yellow", label: "Moderate confidence" },
  low: { threshold: 0, color: "red", label: "Low confidence" },
};

// Display accuracy tier badge next to each stat prediction
function AccuracyBadge({ accuracy }: { accuracy: number }) {
  const tier = accuracy >= 75 ? "high" : accuracy >= 50 ? "medium" : "low";
  return <Badge variant={tier}>{ACCURACY_TIERS[tier].label}</Badge>;
}
```

### Anti-Patterns to Avoid

- **Displaying all stats with equal prominence** - Users need visual cues about which predictions are reliable
- **Hiding prediction intervals** - Creates false confidence in point estimates
- **Trying to improve TD/K/DEF models beyond physical limits** - These are inherently unpredictable
- **Raw accuracy percentages without context** - 20% TD accuracy sounds bad but is expected for rare events

<common_pitfalls>
## Common Pitfalls

### Pitfall 1: Expecting High TD Accuracy

**What goes wrong:** Spending effort trying to improve TD prediction from 20% to 40%
**Why it happens:** TDs are binary outcomes heavily dependent on game script, red zone efficiency, and luck
**How to avoid:** Accept that volume metrics (yards, receptions) are predictable; TDs are not
**Warning signs:** Multiple model iterations with <5% accuracy improvement despite feature engineering

**Evidence from current backtest:**
- RB rushing_tds: 29.2% accuracy, R2=0.659
- WR receiving_tds: 19.6% accuracy, R2=0.598
- TE receiving_tds: 1.9% accuracy, R2=0.500

These are **expected** for rare-event prediction. Research confirms "AI sports prediction models achieve 65-75% accuracy" for general outcomes, with TD-specific predictions much lower.

### Pitfall 2: Misleading Accuracy Metrics

**What goes wrong:** Showing "80% accuracy" when that only applies to volume stats
**Why it happens:** Aggregating accuracy across stat types creates misleading impression
**How to avoid:** Display accuracy per stat type, or use weighted averages with clear explanation
**Warning signs:** Users disappointed when TD predictions miss; they expected 80% overall accuracy

### Pitfall 3: Ignoring Calibration

**What goes wrong:** Model says "80% confident" but is right only 60% of the time
**Why it happens:** Point predictions without interval validation
**How to avoid:** Visualize calibration curves; track if predicted coverage matches actual coverage
**Warning signs:** Prediction intervals from MAPIE consistently over/under-cover

### Pitfall 4: Chart Overload

**What goes wrong:** Showing too many visualizations overwhelms users
**Why it happens:** Developer excitement about data vs user needs
**How to avoid:** Prioritize: (1) point prediction, (2) confidence interval, (3) historical trend. Everything else is secondary.
**Warning signs:** Users skip visualizations and just look at the number
</common_pitfalls>

```typescript
// Source: Recharts API + project patterns
import { ComposedChart, Area, Line, XAxis, YAxis, Tooltip, ResponsiveContainer } from "recharts";

interface PredictionData {
  label: string;
  predicted: number;
  lower: number;
  upper: number;
  actual?: number;
}

export function PredictionIntervalChart({ data }: { data: PredictionData[] }) {
  return (
    <ResponsiveContainer width="100%" height={200}>
      <ComposedChart data={data}>
        <XAxis dataKey="label" fontSize={12} />
        <YAxis domain={["auto", "auto"]} fontSize={12} />
        <Tooltip />
        {/* Confidence band - use two areas */}
        <Area
          type="monotone"
          dataKey="upper"
          stroke="none"
          fill="hsl(var(--primary))"
          fillOpacity={0.15}
        />
        {/* Center prediction line */}
        <Line
          type="monotone"
          dataKey="predicted"
          stroke="hsl(var(--primary))"
          strokeWidth={2}
          dot={false}
        />
        {/* Lower bound as separate line */}
        <Line
          type="monotone"
          dataKey="lower"
          stroke="hsl(var(--primary))"
          strokeWidth={1}
          strokeDasharray="4 4"
          dot={false}
        />
        <Line
          type="monotone"
          dataKey="upper"
          stroke="hsl(var(--primary))"
          strokeWidth={1}
          strokeDasharray="4 4"
          dot={false}
        />
        {/* Actual values when available */}
        {data.some(d => d.actual !== undefined) && (
          <Line
            type="monotone"
            dataKey="actual"
            stroke="hsl(var(--success))"
            strokeWidth={2}
            dot={{ r: 4, fill: "hsl(var(--success))" }}
          />
        )}
      </ComposedChart>
    </ResponsiveContainer>
  );
}
```

### Model Accuracy Summary Component

```typescript
// Component to display per-stat accuracy with trust indicators
interface StatAccuracy {
  stat: string;
  accuracy: number;
  confidence: "high" | "medium" | "low";
  r2: number;
}

export function ModelAccuracySummary({ stats }: { stats: StatAccuracy[] }) {
  const confidenceColors = {
    high: "bg-green-100 text-green-800",
    medium: "bg-yellow-100 text-yellow-800",
    low: "bg-red-100 text-red-800",
  };

  return (
    <div className="grid grid-cols-2 gap-2">
      {stats.map((stat) => (
        <div key={stat.stat} className="flex items-center justify-between p-2 rounded-md bg-muted/30">
          <span className="text-sm">{stat.stat}</span>
          <span className={`text-xs px-2 py-0.5 rounded ${confidenceColors[stat.confidence]}`}>
            {stat.accuracy.toFixed(0)}%
          </span>
        </div>
      ))}
    </div>
  );
}
```

### Backend Calibration Data Endpoint

```python
# Source: sklearn docs + project patterns
from sklearn.calibration import calibration_curve
from mapie.metrics import regression_coverage_score

def compute_model_diagnostics(
    y_true: np.ndarray,
    y_pred: np.ndarray,
    y_lower: np.ndarray,
    y_upper: np.ndarray,
) -> dict:
    """Compute diagnostic metrics for model visualization."""

    # Coverage: what % of actuals fall within predicted intervals
    coverage = regression_coverage_score(y_true, np.column_stack([y_lower, y_upper]))

    # Mean interval width
    mean_width = np.mean(y_upper - y_lower)

    # Residual analysis
    residuals = y_true - y_pred
    residual_std = np.std(residuals)

    return {
        "coverage": float(coverage),
        "target_coverage": 0.90,  # 90% confidence intervals
        "mean_width": float(mean_width),
        "residual_std": float(residual_std),
        "is_calibrated": abs(coverage - 0.90) < 0.05,  # Within 5% of target
    }
```
