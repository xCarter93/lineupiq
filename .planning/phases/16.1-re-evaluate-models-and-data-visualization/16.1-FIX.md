**Root Cause:** `stroke="hsl(var(--primary))"` uses HSL wrapper around a CSS variable that contains OKLCH values (e.g., `oklch(0.60 0.13 163)`). The browser interprets this as malformed HSL, rendering white/transparent.

**Issue:** "I do actually see the points but it doesn't draw it as a line chart or anything that you can see, the points are white so they are barely visible but I feel like we should show a line chart or area chart where the chart is clearly visible."

**Expected:** Chart shows visible line and points with clear coloring.

**Fix:**
1. Replace `stroke="hsl(var(--primary))"` with an explicit color value that works:
   - Use emerald green: `stroke="#10b981"` (matches primary brand color)
   - Or use Tailwind's emerald-500 equivalent

2. Also fix the `dot` props to ensure points are visible:
   - Add `fill` property matching the stroke color
   - Ensure dots have visible stroke

3. Consider converting to AreaChart for better visibility:
   - Replace LineChart with AreaChart
   - Add a gradient fill under the line
   - This makes the data trend more visually prominent

**Recommendation:** Use AreaChart with gradient fill for best visibility. Example:
```tsx
<AreaChart data={sortedData}>
  <defs>
    <linearGradient id="colorFpts" x1="0" y1="0" x2="0" y2="1">
      <stop offset="5%" stopColor="#10b981" stopOpacity={0.3}/>
      <stop offset="95%" stopColor="#10b981" stopOpacity={0}/>
    </linearGradient>
  </defs>
  ...
  <Area
    type="monotone"
    dataKey="fantasyPoints"
    stroke="#10b981"
    strokeWidth={2}
    fill="url(#colorFpts)"
  />
</AreaChart>
```
